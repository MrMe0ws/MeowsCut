# 05. UI, таймлайн-доска и ViewModels

## 5.1 Один интерфейс вместо «простого» и «PRO» режимов

Два режима означали бы две вёрстки, два набора ViewModels и вечный вопрос «что происходит с
правками при переключении». Вместо этого — **одна доска монтажа**, плюс два переключателя
плотности там, где это реально нужно:

- **Панель экспорта:** «Базовые» ↔ «Расширенные» (профиль, уровень, GOP, pix_fmt, два прохода,
  tune, каналы аудио). Состояние запоминается.
- **Таймлайн:** компактная высота дорожки ↔ увеличенная (миниатюры + волна аудио).

Пустой экран остаётся простым (drop zone + недавние), но как только файл открыт — сразу доска.
Никаких «упрощённых» экранов, из которых потом надо куда-то переключаться.

## 5.2 Экраны

**Пустое состояние:**

```
┌────────────────────────────────────────────────┐
│ Meows Cut                                  ⚙   │
├────────────────────────────────────────────────┤
│            ⬚  Перетащите видео сюда            │

│              [  Открыть видео  ]               │
│        Недавние:  clip.mp4 · rec_02.mov        │

```

**Рабочий экран (доска монтажа):**

│ │ clip 1   ││ clip 2  (2x)   ││ clip 3      ││  1080p30 · ~24 МБ    │
│ │ ▂▃▅▃▂ ▁▃ ││ ▂▅▇▅▂          ││ ▁▂▃▂▁       ││  [ Экспорт → ]       │

Слева — источники проекта (bin), центр — плеер последовательности, снизу — дорожка с клипами,
справа — инспектор выбранного клипа и блок экспорта. Панель инструментов доски — над таймлайном.

**Экспорт:** сводка → прогресс (проценты, прошло, осталось, «Обработка видео (2 из 3)»,
кнопка «Отмена») → результат («Готово · 24.1 МБ», «Открыть файл» / «Открыть папку»).

## 5.3 Инструменты доски

| Инструмент | Клавиша | Поведение |
|---|---|---|
| Выделение | `V` | выбрать клип, тянуть края (trim), двигать по ленте; повторный клик снимает выделение |
| Ножницы | `C` | клик по клипу режет в точке курсора |
| Протяжка | средняя кнопка / `Space`+drag | панорамирование таймлайна (ADR-16) |
| Зум | `Ctrl`+колесо | масштаб шкалы времени |

Свойства в панели применяются ко всему выделению: выделив три куска и нажав «2×»,
ускоряются все три. Скорость задаётся и числом, не только кнопками-заготовками.

Перетаскивание клипа меняет его место во времени — между кусками появляется зазор.
Порядок меняется, только когда клип переваливает серединой за середину соседа.

Дополнительно: `S` — разрезать под плейхедом, `Del` — удалить клип с подтягиванием,
`Ctrl+C` / `Ctrl+X` / `Ctrl+V` — копировать, вырезать, вставить у плейхеда,
`I`/`O` — задать in/out выделенного клипа по позиции плейхеда,
`Ctrl+A` — выделить всё, `Ctrl+D` — дублировать,
`Ctrl+Z` / `Ctrl+Shift+Z` — undo/redo, `Space` — play/pause,
`←`/`→` — кадр, `Shift+←/→` — секунда, `Home`/`End` — начало/конец, `Ctrl+E` — экспорт.

Снап (прилипание) — к плейхеду, к границам соседних клипов и к нулю; порог 8 px, отключается
галочкой и временно — зажатым `Alt`.

## 5.4 Предпросмотр последовательности

Плеер обязан играть **результат монтажа**, а не исходник: с учётом порядка клипов, точек in/out
и скорости.

```csharp
interface IMediaPlayer                     // обёртка над WPF MediaElement, тестируемая
{
    Task OpenAsync(string path);
    void Play(); void Pause();
    TimeSpan Position { get; set; }
    double SpeedRatio { get; set; }
    double Volume { get; set; }
    event EventHandler? MediaEnded;
}

sealed class SequencePlaybackController    // App/Playback
{
    TimeSpan Position { get; }             // время на таймлайне
    void Seek(TimeSpan timelineTime);      // Sequence.Resolve → (clip, sourceTime)
    void TogglePlay();
    void StepFrames(int delta);
}
```

Как работает: контроллер держит один `IMediaPlayer`, по таймеру (~30 Гц) сопоставляет позицию
исходника с позицией на таймлайне, у границы клипа переключает файл/позицию и выставляет
`SpeedRatio` и громкость следующего клипа.

**Честное ограничение:** на стыке клипов будет заметный подскок (seek у `MediaElement` не
мгновенный), особенно между разными файлами. Это принято сознательно: полноценный
кадроточный композитор — это второй движок размером со всё приложение. Смягчения:
предзагрузка следующего клипа во второй скрытый плеер (v1.1) и кнопка **«Проверить фрагмент»**,
рендерящая 5–10 секунд реальным пайплайном экспорта.

Фильтры экспорта (масштаб, FPS, кодек) в плеере не применяются — они не меняют содержание кадра.
Кроп/поворот, когда появятся, будут накладываться поверх плеера как трансформация вывода.

## 5.5 ViewModels

```
ShellViewModel                        состояние: Empty | Editing | Exporting; undo/redo команды
├─ ProjectViewModel                   источники, Sequence, EditHistory
│   ├─ SourceBinViewModel             список файлов, добавление, перетаскивание на таймлайн
│   ├─ PreviewViewModel               SequencePlaybackController, транспорт, плейхед
│   ├─ TimelineViewModel              зум, скролл, снап, активный инструмент, выделение
│   │   └─ ClipViewModel[]            позиция/ширина, миниатюры, волна, drag-состояние
│   └─ InspectorViewModel             свойства выделенного клипа (in/out, скорость, звук)
├─ ExportViewModel                    сводка, базовые/расширенные параметры, запуск, прогресс
├─ PresetsViewModel                   группы пресетов, Telegram Stickers
├─ SettingsViewModel                  путь к ffmpeg, тема, папка вывода, логи
└─ FfmpegSetupViewModel               онбординг, если ffmpeg не найден
```

Правила:

- Базовый `ObservableObject` (CommunityToolkit.Mvvm), `[ObservableProperty]`, `[RelayCommand]`.
- **Любое изменение последовательности — только через `EditHistory.Execute(command)`.**
  ViewModel не мутирует `Sequence` напрямую, иначе undo сломается.
- `ClipViewModel` — тонкая проекция клипа на пиксели (`X`, `Width` от зума), пересоздаётся
  по событию `EditHistory.Changed`; идентичность по `ClipId`, чтобы не терять выделение.
- Длительные команды — `IAsyncRelayCommand` с `CancellationToken`.
- ViewModel не знает про ffmpeg: только `IMediaProbe`, `IJobQueue`, `IExportPlanner`,
  `IPresetProvider`, `IThumbnailService`, `IWaveformService`.
- Обновление UI из фоновых потоков — через `IUiDispatcher`.
- Связь между VM — `WeakReferenceMessenger` (`SelectionChangedMessage`, `PlayheadMovedMessage`).

## 5.6 Контрол таймлайна

`TimelineControl` — кастомный `Control` с ручной отрисовкой (`OnRender`), а не `ItemsControl`:
при сотнях миниатюр и волне дерево элементов проседает.

Слои: фон и разметка времени → миниатюры клипов → волна аудио → рамки и подписи клипов →
выделение → ручки обрезки → плейхед → оверлей перетаскивания.

Взаимодействие: hit-testing по зонам (тело клипа / левая ручка / правая ручка), режим курсора
зависит от активного инструмента, drag превращается в серию команд с `TryMergeWith`.
Миниатюры и волна подгружаются лениво по видимой области, запросы отменяются при скролле.

Виртуализация: рисуется только видимый диапазон времени; миниатюры кэшируются по
(`source`, `время`, `ширина`).

## 5.7 Оформление

- Тёмная тема по умолчанию, светлая опцией. Один акцентный цвет.
- Плотная, но не мелкая сетка: приоритет — таймлайн и плеер, панели не съедают место.
- Термины называются прямо; подсказка — одна строка, не мастер.
- Предупреждения (апскейл, VFR-источник, несовместимый кодек) — иконкой рядом с полем,
  с раскрытием по наведению, без модальных окон.

## 5.8 Drag & drop и поддерживаемые форматы

- `DragDropFileValidator` проверяет расширение по списку, для незнакомых спрашивает ffprobe.
- Расширения: mp4, m4v, mov, mkv, webm, avi, wmv, flv, ts, m2ts, mts, mpg, mpeg, 3gp, ogv, gif.
  Последнее слово за ffprobe: открылся — работаем.
- Несколько файлов за раз добавляются в источники и (по выбору в диалоге) ставятся встык
  на дорожку — модель клипов это поддерживает изначально.
